<h1 align="center">📅 GCal Utils</h1>

<p align="center">
  <strong>たくさんのカレンダーを重ねて見るときの Google Calendar を片付ける。</strong><br/>
  重複した予定のマージ、regex による予定の非表示、ワンクリックでの 1 カレンダー表示ができる Chrome 拡張です。
</p>

> [!WARNING]
> Experimental です。GCal Utils は Google Calendar の非公開のページ構造を読み書きしているため、Google 側の変更で予告なく動かなくなることがあります。

## Why GCal Utils?

- **重複した予定のマージ**：5 人が参加する会議は、細いチップ 5 つが横に並ぶ代わりに 1 つで表示されます。各カレンダーの色は左端の色帯として残ります
- **regex による予定の非表示**：見る必要のない予定をグリッドから消します。隠した予定があることは、日付ヘッダーの `⊘N` バッジで分かります
- **1 カレンダーだけの表示 (solo)**：1 クリックでそのカレンダーだけを表示し、もう 1 クリックで直前に表示していたカレンダーに戻します

## 🚀 Quick Start

**前提:** Chrome、または Manifest V3 に対応した Chromium 系ブラウザー。

1. このリポジトリを clone する
2. `chrome://extensions/` を開く
3. 「デベロッパー モード」を有効にする
4. 「パッケージ化されていない拡張機能を読み込む」でリポジトリのディレクトリを選ぶ

calendar.google.com を週ビューで開きます。表示中の複数のカレンダーに入っている会議が、1 つのチップになっていれば動いています。インストール前から開いていたタブは再読み込みが必要です。Chrome は、インストール後に読み込んだページにだけ content script を入れるためです。

GCal Utils を止めるには、拡張の popup で各機能を OFF にするか、`chrome://extensions/` から拡張を削除します。

## 📖 Usage

マージと非表示の対象は、日、週、カスタム日数ビューの時間グリッドと終日行です。月、年、スケジュールビューは変更しません。

### 重複した予定のマージ

Google の event ID が同じ予定、または同じ日 (終日行では同じ位置) でタイトルと開始と終了が同じ予定を、同じ予定とみなします。event ID での判定は 1 つの招待が複数のカレンダーに出ているケースを拾い、内容での判定は別々に作られたコピーも拾います。

まとめた予定には次のものが付きます。

- 左端に、カレンダーごとの色の色帯
- タイトルの前に、カレンダー数を示す `×N` バッジ
- hover したときのカレンダー一覧

承諾済みのコピーと承諾していないコピーが混ざっている場合は、承諾済みのコピーを残します。

マージの後、日ごとに残った予定を重ならないように並べ直し、消えたコピーが使っていた幅を残った予定が使います。終日行では、空いた行へ予定を上に詰め、終日エリア自体も低くなります。

### regex による予定の非表示

拡張の popup に 1 行 1 pattern で入力します。各行は JavaScript の正規表現として、大文字小文字を区別せずに予定のタイトルと照合します。不正な pattern は入力中にテキストボックスの下に表示されます。例:

```
^Lunch$
Focus time
```

隠した予定がある日は、日付ヘッダーに `⊘N` バッジが出ます。バッジに hover すると、隠した予定のタイトル一覧が出ます。隠した予定が使っていた場所は、マージと同じように詰めます。

### Solo mode

左サイドバーのカレンダーに hover すると、行の右端に `S` ボタンが重なって出ます。行の幅は変わりません。クリックするとそのカレンダーだけを表示します。同じボタンをもう一度クリックすると、solo を始める前に表示していたカレンダーに戻ります。元々非表示だったカレンダーは非表示のままです。

solo 中に別のカレンダーの `S` をクリックすると、表示対象だけがそのカレンダーに切り替わり、戻り先は最初の状態のまま保たれます。GCal Utils は Google のチェックボックスを代わりにクリックしてカレンダーを切り替えるため、結果は手で切り替えたときと同じです。戻り先は `chrome.storage.local` に保存され、ページを再読み込みしても残ります。

## ⚙️ Configuration

設定はすべて拡張の popup にあり、`chrome.storage.sync` に保存されます。

| 設定 | 既定値 | 内容 |
|---|---|---|
| Merge duplicate events | On | 同じ予定のコピーを 1 つにまとめる |
| Hide events by regex | On | タイトルが hide pattern にマッチする予定を隠す |
| Solo button on calendar list | On | サイドバーに `S` ボタンを出す |
| Hide patterns | 空 | 1 行 1 つの正規表現。大文字小文字を区別しない |

## 🔒 Permissions

- `storage`：設定と、solo の後に戻すカレンダーの保存

## 🧪 Development

build step も依存パッケージもありません。

| ファイル | 役割 |
|---|---|
| `core.js` | DOM に触れない純粋関数 (event ID の decode、重複のグルーピング、レイアウト)。テストの対象 |
| `content.js` | カレンダーのグリッド上で予定をマージ、非表示、再配置する |
| `solo.js` | サイドバーのカレンダー一覧に solo ボタンを付ける |
| `content.css` | 色帯、バッジ、hover 一覧、solo ボタンのスタイル |
| `popup.html`、`popup.js` | 設定の popup |

テストは Node.js 組み込みのテストランナーで実行します (Node.js 26 で確認)。

```sh
node --test
```

変更を試すには、`chrome://extensions/` で GCal Utils の再読み込みボタンを押してから、Google Calendar のタブを再読み込みします。

## 🔧 Troubleshooting

### 予定がマージされない

- 日、週、カスタム日数ビューのどれかを開いているか確かめる
- popup で「Merge duplicate events」が ON になっているか確かめる
- 拡張のインストールや再読み込みより前から開いていたタブなら、再読み込みする
- 両方のコピーを開いて比べる。event ID が異なるコピーは、タイトルと開始と終了がすべて同じでないとマージしない

### ドラッグした後に予定の位置がずれる

マージや再配置をした予定は、Google のドラッグ処理と位置が合わないことがあります。ドラッグする前に popup で該当する機能を OFF にするか、ドラッグした後にページを再読み込みします。

### solo ボタンが出ない

- popup で「Solo button on calendar list」が ON になっているか確かめる
- 左サイドバーが閉じていれば開く
